# EXIT Design Bible
## 34 — Convention linguistique

**Statut :** 🟢 Convention éditoriale  
**Dernière mise à jour :** 17 septembre 2026

## Règle

La documentation de conception d'EXIT est rédigée en français. Les anglicismes ne sont conservés que lorsqu'ils désignent un sigle établi, un nom propre, une référence historique, un identifiant de données ou un terme d'outillage dont la traduction nuirait à la précision.

## Vocabulaire préférentiel

| Employer dans la documentation | Référence anglaise admise si utile |
|---|---|
| état du monde | `World State` |
| fait du monde | `World Fact` |
| connaissance | `Knowledge` |
| mémoire | `Memory` |
| croyance | `Belief` |
| besoin | `Need` |
| but | `Goal` |
| objectif | `Objective` |
| stratégie | `Strategy` |
| plan | `Plan` |
| tâche | `Task` |
| action | `Action` |
| quête | `Quest` |
| gestionnaire de quêtes | `QuestManager` |
| retour d'information | `Feedback` |
| revue de conception | `Design Review` |
| registre des sujets à traiter | `Backlog` |

## Exceptions acceptées

- `NPC`, `GOAP`, `AND/OR`, `UI/UX`, `C++` et les noms de fichiers restent inchangés lorsqu'ils servent d'identifiant ou de référence technique.
- Les titres, noms de fichiers ou citations de sources historiques en anglais sont conservés comme titres propres, éventuellement accompagnés d'une explication française.
- Les exemples de pseudo-données peuvent conserver un identifiant anglais, par exemple `EXIT_A.open == true`.

Cette convention n'établit aucune décision de game design ; elle garantit seulement une documentation lisible et cohérente.
